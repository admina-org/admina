# Admina 0.10.0 — Design (v2)

Status: **approved scope, pending spec review**
Date: 2026-06-09 · Revised: 2026-06-10 (v2 — structural-debt repayment incorporated after the architecture & functionality review)
Owner: Stefano Noferi
Predecessor release: 0.9.5 · Next minor: 0.10.0

0.10.0 is a **debt-repayment + feature** release. The architecture review
(`docs/superpowers/audits/2026-06-10-architecture-functionality-review.md`)
identified nine structural debts; the ones rated "pay at 0.10" are paid
here, before/with the feature work that would otherwise cement them.

---

## 0. Scope and non-goals

**In scope — structural debts:**

- **D1** Unified engine acquisition (`admina/engines/`).
- **D2** One canonical governance pipeline, all Admina-owned surfaces
  delegate; full protection ON by default on `GovernedModel`.
- **D3** Plugin third-party loop repaired (extended set).
- **D4** Config bugs only (`cfg.raw`, OISG S2, `schema_version`).
- **D6** Forensic cheap fixes (write lock + wired chain verification).
- **D8** Deduplicate drifted artifacts (SDK ABCs, dashboard SPA, token
  verifier).
- **D-docs** Honesty pass: docs claims aligned with wired reality.

**In scope — features:**

1. Model adapters — Anthropic, Mistral, AWS Bedrock, Google Gemini, vLLM.
2. Presidio PII engine — selectable alternative, EN + IT default.
3. Dashboard WebSocket auth — single-tenant (regression fix, unified
   auth, Origin check, one coarse scope).
4. Retry / backoff — opt-in policy on the governed primitives.
5. Release mechanics — version bump, extras, template fixes.

**Deferred:**

- SDK streaming → 0.11 (design spike during 0.10). Streaming-aware retry
  co-designed there.
- **D5** audit spine via event bus + **D7** observability + **D9**
  forensic write-path performance → 0.11.
- Config system unification (beyond D4 bug fixes) → 0.11–0.12.
- **D6** state-backend seam (per-process state) → before 0.12.
- Moving the 9 plugin ABCs to `core/ports.py` → revisit pre-1.0, not now.
- LangChain/CrewAI **enforcement** (the callback mechanism is
  observational by nature; redesign deferred — 0.10 documents the
  detection-only reality honestly).
- Multi-tenant / RBAC / SSO → 0.12+ / commercial line.

## 1. Debt repayment

### D1 — Unified engine acquisition: `admina/engines/`

Today `proxy/engine_bridge.py` owns Rust auto-detection and the
admina.yaml firewall overrides; SDK (`governed_agent.py:55-73`,
`governed_model.py:76-80`) and `integrations/_engines.py:30-63` construct
pure-Python engines directly. Same domain, three acquisition paths, only
one accelerated/configurable.

Design:

- New package **`admina/engines/`** (sits beside `domains`, below
  `sdk`/`proxy`/`integrations` in the dependency graph): move the bridge
  logic out of the proxy. Public surface: `get_firewall()`,
  `get_pii_engine()`, `get_loop_breaker()` — the single acquisition
  point for every consumer.
- Selection: `ADMINA_ENGINE=auto|python|rust` (env + config), default
  `auto` (today's Rust auto-detect behaviour preserved).
- admina.yaml overrides (firewall `custom_patterns`/`disabled_categories`)
  applied in `admina/engines`, so **all** surfaces honour them.
- **Fix the `cfg.raw` bug** (`engine_bridge.py:55-63` reads an attribute
  that never exists — YAML overrides can never load today). The D1 rework
  replaces this code path.
- **Fix the firewall category-name drift** (`role_hijacking` vs
  `role_hijack` breaks `disabled_categories`): one canonical category
  vocabulary, mapping for the Rust engine.
- `proxy/engine_bridge.py` becomes a thin re-export shim (back-compat for
  any external import).
- `integrations/_engines.py` and the SDK `_load_*` helpers delegate to
  `admina/engines`.
- **Presidio selection** (`cfg.pii_engine`: `spacy-regex` | `presidio`)
  lives here — one resolver, all surfaces. `pii_engine="presidio"`
  explicit takes precedence over Rust auto-detection (Rust accelerates
  only the `spacy-regex` path).

### D2 — One canonical pipeline, all surfaces delegate

Today the same three engines are orchestrated five different ways with
different stage subsets, orderings, and action vocabularies; only
`POST /mcp` runs the documented pipeline.

Design:

- **Promote `run_pipeline`** from `proxy/governance.py` to
  `admina/domains/governance.py`. It stays exactly what it is — pure
  logic, engines/guards/mode injected, zero I/O. The proxy module
  re-exports for compat.
- **Single canonical order:** loop → firewall → PII → guards (the
  current `/mcp` order). One action vocabulary: kill `MODIFY` (use
  `REDACT`), fix `risk_level` casing.
- **All Admina-owned surfaces delegate:**
  - `proxy POST /mcp` — already does; now also fixes the dead
    response-side PII for dict-shaped MCP results (`main.py:1373-1376`
    passes dicts through; reuse the deep-dict redaction GovernedAgent
    already has).
  - `proxy /api/v1/validate` — gains guards + `GOVERNANCE_MODE` honour,
    loses its private vocabulary.
  - `GovernedAgent.call()` — stops hand-rolling (today firewall→loop,
    canonical is loop→firewall). **Session fix:** a `GovernedAgent`
    instance holds a stable session id (today a fresh `uuid4` per call
    makes the loop breaker structurally inert).
  - `GovernedModel.ask()` — gains the pipeline. **Default: full
    protection ON** — firewall on the request, PII in/out, loop breaker
    when a `session_id` is provided, guards if registered. Per-stage
    opt-out constructor flags. This is a deliberate pre-1.0 behaviour
    change, declared loudly in the CHANGELOG.
  - LangChain/CrewAI callbacks — **not** delegated (observational
    mechanism, cannot mutate the flow); covered by D-docs instead.
- **Guard contract errors become loud:** today a scaffolded guard with a
  sync method silently never enforces (TypeError swallowed at
  `governance.py:116-117`). The canonical pipeline logs guard contract
  violations at ERROR with the plugin name.

### D3 — Plugin third-party loop repaired

(Supersedes the v1 "prerequisite fixes"; all of v1 plus:)

- `_extract_name` (`registry.py:331-370`): name-based identity via a
  class-level `name` attribute convention; applied to all builtins.
- Scaffold `plugin.py.j2`: `async def send(...)` matching the ABC, and
  the generated `pyproject.toml` gains the `[project.entry-points."admina.plugins"]`
  section so a scaffolded plugin is discoverable without manual yaml.
- `plugin_pyproject.toml.j2`: package name `admina` → `admina-framework`,
  current version pin.
- **`discover()` consumes `AdminaConfig.plugins`** (today the yaml
  `plugins:` list is parsed and never passed to the registry).
- **Config passing:** when a plugin `__init__` accepts a `config`
  parameter, the registry passes the plugin's admina.yaml block at
  instantiation.
- **Integration test pinning the loop:** scaffold a plugin via the CLI
  templates → load it through the registry → execute its contract
  method. The third-party story gets a test that fails when any seam
  breaks again.

### D4 — Config bugs (unification deferred)

- `cfg.raw` — fixed by D1.
- OISG S2 false negative in the proxy score bridge (`main.py:64-70` area).
- `schema_version` vs `version` key drift in config parsing.
- `admina init` templates: stop scaffolding keys nothing reads — after
  D1/D2, `pii_engine` is live; remaining dead keys are either wired or
  removed from the template.

### D6 — Forensic cheap fixes

- **Write lock** around `ForensicBlackBox.record()`'s read-modify-write
  of `chain_head` (`forensic.py:205-236`) — two concurrent writers fork
  the chain silently today.
- Filesystem backend: duplicate-sequence writes fail loudly instead of
  silently overwriting.
- **Chain verification wired into a real path:** `admina doctor` runs it
  and a `GET /api/v1/forensic/verify` endpoint exposes it (today
  verification exists but is never invoked by any wired path).
- The state-backend seam and multi-writer chain design stay deferred
  (pre-0.12).

### D8 — Deduplicate drifted artifacts

- **Delete the SDK-local ABCs** (`BaseModelAdapter` in
  `governed_model.py:35-58`, `BaseDataConnector` in
  `governed_data.py:35-46`); import from `plugins/base.py` and keep the
  names re-exported from the sdk modules so existing user imports keep
  working. Fixes the quickstart type error under `py.typed`.
- **Single-source the dashboard SPA:** `admina/dashboard/static/` is
  canonical (it ships in the wheel and got the latest fixes); the
  repo-root `dashboard/` copy is removed and the dashboard Docker image
  serves the packaged copy. One artifact, no drift.
- **One token verifier** for HTTP and WS — delivered by the WS-auth
  workstream (§3 of the features), referenced here as the D8 instance.

### D-docs — Honesty pass

Claims the review proved wrong get fixed — code-side where cheap,
docs-side where the mechanism is the limit:

- **Luhn:** implement actual Luhn validation in the Python PII engine
  (docs promise it; neither engine has it). Rust engine unchanged in
  0.10 — the difference is noted in MODEL_CARD.
- **Pipeline order:** the three docs showing three different (all wrong)
  orders are aligned to the one canonical order from D2.
- **MODEL_CARD "behaviorally equivalent engines":** rewritten to state
  the measured 7/14 vs 14/14 evasion parity, consistent with the
  README's existing honest disclosure.
- **LangChain/CrewAI:** "PII redaction" wording corrected to
  detection-only (alerting/audit), with the enforcement limitation
  stated.
- **Sidecar bootstrap (n8n/CheshireCat/OpenClaw):** fix the documented
  bootstrap (the entrypoint requires an API key the setup never
  provides) and make the 401 → permanent-fail-open path log loudly;
  OpenClaw SKILL.md wire schema corrected.

## 2. Model adapters

(Unchanged from v1, now standing on D1+D3.)

New files in `admina/plugins/builtin/adapters/`: `anthropic.py`,
`mistral.py`, `bedrock.py`, `gemini.py`, `vllm.py`.

- Each: subclass `BaseModelAdapter` (the **single** ABC, post-D8), lazy
  SDK import with actionable `ImportError` naming the extra, token
  normalization to `{tokens, latency_ms, model}`.
- Bedrock: boto3 `bedrock-runtime` Converse API via `asyncio.to_thread`;
  standard AWS credential chain.
- Gemini: `google-genai` (current SDK, not legacy).
- vLLM: thin subclass of `OpenAIAdapter`, `base_url` default
  `http://localhost:8000/v1`, `name='vllm'`, `supports_model` always True.
- Registered under name-based identity (`anthropic`, `mistral`, …) per D3.
- Default model ids pulled from live provider docs / `claude-api` skill
  at implementation time — never hardcoded from memory.
- No auto-routing helper in 0.10 (explicit decision); `supports_model()`
  implemented correctly for a future selector.
- ABC stays at three methods; streaming surface arrives in 0.11.

Tests: per-adapter mock-`_client` pattern, `importorskip` guards,
registry name-key assertions.

## 3. Presidio PII engine

(Mechanics unchanged from v1; selection now lives in `admina/engines`.)

- New `admina/plugins/builtin/pii/presidio.py` — `PresidioEngine`
  producing the sync `redact() -> {redacted_text, entities, count}`
  shape (drop-in for every current consumer), built on
  `AnalyzerEngine` (EN + IT spaCy models) + `AnonymizerEngine`.
- Mask parity via per-entity `OperatorConfig('replace', …)` —
  `[LOCATION]`/`[CF]`/`[DNI]` tokens preserved; `DataClassifier`
  unaffected.
- The audited EU-ID regex pass stays alongside Presidio (no recall loss).
- Selection: `cfg.pii_engine` resolved in `admina/engines` (D1) — one
  switch, effective on every surface.
- `PIIConfig` gains `language(s)`; `supported_languages` reflects
  installed models.
- New `[presidio]` extra; the `it_core_news_sm` download step documented
  like the existing `[nlp]` note.

Tests: engine contract, config selection, Italian detection, mask parity.

## 4. Dashboard WebSocket auth — single-tenant

(Unchanged from v1; explicitly the D8 verifier-unification instance.)

1. Fix the regression: WS cookie branch validates the signed token via
   the shared verifier (injected into `create_dashboard_endpoints`);
   same fix in `apikey.py:136-138`.
2. One auth resolver `(headers, query, cookies) → principal` shared by
   HTTP middleware and WS upgrade.
3. Origin allow-list on the WS upgrade (reuse `CORS_ORIGINS`; absent
   Origin ⇒ non-browser client ⇒ allowed with key auth).
4. One coarse scope (`read` | `full`) in the signed cookie payload,
   enforced on WS subscribe. Stateless, no key store.
5. Header / query-param auth preserved for non-browser clients;
   query-string leakage documented.

Tests: valid/tampered/expired cookie, raw-key-as-cookie rejected, Origin
rejected, scope-denied.

## 5. Retry / backoff

(Unchanged from v1; wraps the post-D2 unified call sites.)

- `admina/sdk/retry.py`: `RetryPolicy` dataclass + vendored
  `run_with_retry(coro_factory, policy, classify)` (~30 LOC, no
  tenacity), exponential backoff + jitter + `Retry-After` + per-attempt
  `asyncio.wait_for`.
- `admina/sdk/errors.py`: `RetryableUpstreamError` / `TerminalUpstreamError`.
- `retry: RetryPolicy | None = None` on the three primitives; wraps only
  the upstream await (post-D2 there is exactly one such site per
  primitive — retry lands **after** D2 to avoid wrapping five).
- Default-deny classifier; governance refusals and `PermissionError`
  never retried.
- Blocking provider clients moved to `asyncio.to_thread` so timeouts
  fire (also fixes the latent event-loop block).
- Retry attempts recorded in the audit trail.
- Env-sourced global defaults (`ADMINA_RETRY_*`) mirroring
  `FORENSIC_S3_*`.
- Streaming interaction documented as a 0.11 constraint.

## 6. Release mechanics

(Unchanged from v1.)

- 0.10.0 across the 7 `check-versions.py` files + 4 lockfiles
  regenerated; `[rust]` pin widened to `>=0.10,<0.11` (range, never `==`);
  admina-core gets a lockstep courtesy bump only.
- Extras: `[anthropic]` `[mistral]` `[bedrock]` `[gemini]` +
  retroactive `[openai]` `[ollama]` + roll-up `[adapters]` +
  `[presidio]` + new meta-extra `[all]`; `full` unchanged.
- Templates fixed and **added to check-versions.py** (no more silent
  drift); docker-compose tag templated from `admina.__version__`.
- CHANGELOG `## [0.10.0]` with the sanctioned headings; the
  GovernedModel default-protection behaviour change called out
  explicitly. Tone: neutral-technical.
- README extras table updated.

## 7. Sequencing

```
Phase 0  D3 plugin-loop fixes · D4 config bugs · D8 dedup (ABCs, SPA)
         — cheap, unblock everything

Phase 1  D1 admina/engines (foundation for Presidio + all surfaces)

Phase 2  D2 canonical pipeline + delegation of the four surfaces
         (depends on D1; includes GovernedModel default change,
          GovernedAgent session fix, /mcp dict-result response PII)

Phase 3  ∥ adapters (5 providers + extras)      — after Phase 0
         ∥ Presidio (engine + selection)        — after Phase 1
         ∥ D6 forensic lock + verify wiring     — independent
         ∥ D-docs honesty pass                  — independent

Phase 4  WS-auth (after the Phase 0 regression fix)
         Retry (after D2 — wraps the unified call sites)

Phase N  Release mechanics last (extras finalized, CHANGELOG, bump)
```

## 8. Verification

- `uv run --all-extras pytest` (plain `uv run pytest` strips extras).
- **New: governance-coherence test** — `test_governance_coherence.py`
  asserts the four delegated surfaces produce identical decisions for
  identical inputs (the review's matrix becomes a pinned test, like the
  existing firewall-parity suite).
- Plugin-loop integration test (D3).
- Forensic: concurrent-writer test + chain-verify endpoint test (D6).
- `importorskip` for every optional SDK; `check-versions.py` green.
- Per-workstream tests as listed in each section.

## 9. Open-core boundary

Unchanged: everything in 0.10 is a generic primitive and stays
Apache-2.0. WS auth capped at single-tenant API-key + one coarse scope;
multi-tenant/RBAC/SSO remain 0.12+/commercial. Strategic rationale lives
in `internal/ROADMAP_INTERNAL.md`, not here.
