# 0.10.0 — running CHANGELOG notes

Accumulated as each plan lands, assembled into the real `CHANGELOG.md`
`## [0.10.0]` section by Plan 07 (release mechanics). Tone: neutral-technical,
Keep-a-Changelog headings (Added/Changed/Removed/Fixed/Documentation/Internal).

---

## Phase 0 (Plan 01) — plugin loop, config, dedup

### Fixed
- Builtin plugins register under their declared `name` (e.g. `ollama`, `apikey`)
  instead of a lower-cased class name.
- `admina plugin new` scaffolds working plugins: async methods matching every ABC,
  `admina-framework` dependency with the correct version floor, Python 3.11 requirement,
  and an `admina.plugins` entry-point so installed plugins are discoverable.
- `admina.yaml` `schema_version` is now parsed (was silently ignored — the loader read a
  nonexistent `version` key).
- OISG criterion S2 ("cryptographic agent identity") reads the configured API key
  instead of a nonexistent attribute.

### Added
- `admina.yaml` `plugins:` list and a new `plugin_config:` block are wired into plugin
  discovery and instantiation; plugins whose `__init__` accepts a `config` parameter
  receive their block.

### Changed
- The duplicated SDK adapter/connector ABCs are removed; `admina.sdk` re-exports the
  canonical `admina.plugins.base` definitions (single type for one contract).
- The dashboard SPA is single-sourced from the packaged copy; the diverged Docker root
  copy is removed.

## Plan 02 (D1) — unified engine acquisition

### Added
- `ADMINA_ENGINE=auto|python|rust` selects the governance engine backend uniformly
  across proxy, SDK, and integrations (unrecognized value raises).
- Typed `agent_security.firewall.custom_patterns` / `disabled_categories` config fields.

### Changed
- Governance engines (firewall, PII, loop breaker) are acquired through a single
  `admina.engines` package. SDK governed primitives and LangChain/CrewAI callbacks now
  gain Rust acceleration (firewall + loop breaker) under `auto` when `admina-core` is
  installed — previously proxy-only.
- SDK and integration callbacks now honor `admina.yaml` firewall overrides — previously
  proxy-only (and, via the broken `cfg.raw` path, effectively nothing).
- The `pii_engine` config key is now live (`spacy-regex` shipped; `presidio` reserved for
  0.10 behind `admina-framework[presidio]`).
- PII redaction stays on the Python engine by default even when Rust is installed
  (recall-safe: the Rust scanner does not cover EU national IDs or NER person/org names);
  Rust PII is opt-in via `ADMINA_ENGINE=rust`. Firewall and loop breaker remain
  Rust-accelerated under `auto`.

### Fixed
- `admina.yaml` firewall `custom_patterns` / `disabled_categories` now actually reach the
  firewall (the previous `cfg.raw` access path never existed, so overrides were dead).
- Rust engine `get_stats()` is normalized to the Python schema (Prometheus metrics were
  silently keyed differently for the Rust backend).
- When firewall overrides are present, `get_firewall()` uses the Python bridge so
  operator patterns are never silently ignored (the Rust firewall API cannot receive
  custom patterns).

### Internal
- `admina/proxy/engine_bridge.py` is now a re-export shim over `admina.engines`.

## Plan 03b — D2 SDK surfaces

### Added
- `run_pipeline` gained an optional `loop_enabled` flag so single-shot SDK callers can skip cross-call loop state (default `True`; server surfaces unchanged).

### Fixed
- `GovernedData.ingest()` now classifies the actual ingested content (a string or a document collection) and no longer misclassifies an opaque source locator (file path, URL) as content; opaque sources are flagged `source_scanned=false`.

### Changed
- `GovernedAgent` now keeps a stable per-instance session so loop detection works across calls, runs loop→firewall (canonical order), redacts PII in dict keys, and redacts non-dict upstream results. The buggy local scan/redact helpers were replaced with the shared collision-safe pipeline helpers.
- BREAKING (pre-1.0): `GovernedModel.ask()` now runs the injection firewall on the prompt and pluggable guards by default (was PII-only) and can return `action="BLOCK"` with empty text. `GovernedResponse` gains an `action` field (default `"ALLOW"`). Opt out per stage via `GovernedModel(firewall_enabled=False, governance_guards=..., loop_detection=...)`. Loop detection runs only when a `session_id` is provided per call.

## Plan 03 — D2 server surfaces

### Fixed
- Firewall/PII scanning now covers dict keys, not just values (injection or PII in a field name is no longer skipped).
- Proxy now redacts PII in dict-shaped MCP tool results (previously only plain-string results were redacted).
- Observe/dry-run "would-have-blocked" decisions now persist to the audit trail and reach the dashboard policy-suggestion engine (previously always zero).
- `/api/v1/validate` now delegates to the canonical governance pipeline: honors `GOVERNANCE_MODE` (observe/dry-run), normalizes `risk_level` casing, and no longer runs PII work after a block. The `MODIFY` action (content was redacted) is unchanged.
- `/api/v1/validate` loop detection (CIRCUIT_BREAK) is now correctly reported as `action="BLOCK"` to REST consumers; previously CIRCUIT_BREAK leaked into the response breaking n8n/CheshireCat/OpenClaw integrations.
- Note: on a blocked `/api/v1/validate` request the `checks` object no longer contains a `pii_redaction` entry (PII is not run after a block); read it with `.get()`.
- A pluggable governance guard that violates its contract is now logged at ERROR and recorded in the decision's checks (was a silent WARNING skip), so a broken guard is visible in the audit trail instead of vanishing.

## Plan 04 — D6 forensic

### Added
- `admina doctor` and `GET /api/v1/forensic/verify` now report forensic hash-chain integrity (verification was previously never invoked by any wired path).

### Fixed
- The forensic store now reconstructs its hash-chain state from the stored records when
  the state file is missing or corrupt, instead of silently restarting the chain from
  GENESIS (which forked/overwrote the audit trail). A corrupt state file is logged at
  ERROR.
- Concurrent forensic record writes are now serialized (threading lock), preventing chain
  forks from interleaved increments of the sequence number / chain head.
- `verify_chain` now anchors a full verification against the persisted record count and
  chain head, so a truncated tail (records deleted after the last linked one) is detected
  as invalid instead of trivially passing.
- The FilesystemForensicStore plugin now reconstructs chain state from records (no silent GENESIS reset), serializes appends, refuses to overwrite an existing record file, and detects tail truncation in verify_chain — matching the ForensicBlackBox hardening.

## Plan 05 — WS & auth

### Fixed
- The bundled dashboard's live WebSocket feed now authenticates via the signed admina_session cookie (it previously compared the signed token against the raw API key and always failed when a key was set).
- The built-in API-key auth provider now accepts the signed admina_session dashboard cookie (it previously treated the cookie as a raw key and rejected valid browser sessions; since this provider runs first in the middleware, that broke the cookie path entirely).

### Security
- The dashboard WebSocket upgrade now enforces an Origin allow-list (CORS_ORIGINS) to mitigate Cross-Site WebSocket Hijacking; absent-Origin (non-browser) clients still require a valid credential, and '*' in CORS_ORIGINS allows any origin (opt-in).
- Closed a fail-open default: a proxy with no ADMINA_API_KEY no longer authenticates every request as admin via the keyless built-in API-key provider. The keyless provider is fail-closed and is not loaded; with no key and no auth providers the proxy rejects protected requests unless ALLOW_UNAUTHENTICATED=true is explicitly set, and logs a loud startup warning.

### Internal
- HTTP, WebSocket, and provider auth now share one credential verifier (raw key or signed cookie) so they cannot drift.

## Plan 06 — correctness

### Fixed
- EU AI Act gap analysis now pads each requirement's declared checks to the canonical count, so supplying a bool or a short list no longer inflates the compliance score to a false COMPLIANT (unspecified checks count as unmet).
- `generate_report` accepts a bare `bool` in `current_compliance` without raising `TypeError` (the engine now coerces bools via `_coerce_checks` before iteration).
- Credit-card PII detection now validates the Luhn checksum (Python engine), matching the documented behavior and eliminating false positives on arbitrary 16-digit numbers.
- The SpaCyRegexPIIEngine plugin now merges overlapping detections into non-overlapping spans before redaction, preventing text corruption and leftover PII fragments when two patterns (or a regex and an NER entity) overlap.

## Plan 07 — adapters

### Added
- Anthropic model adapter (`admina-framework[anthropic]`).
- Mistral model adapter (`admina-framework[mistral]`): wraps `mistralai.client.Mistral` chat completions, env `ADMINA_MISTRAL_API_KEY`/`ADMINA_MISTRAL_MODEL`.
- AWS Bedrock model adapter (`admina-framework[bedrock]`): wraps `boto3` Converse API, standard AWS credential chain, env `ADMINA_BEDROCK_REGION`/`ADMINA_BEDROCK_MODEL`.
- Google Gemini model adapter (`admina-framework[gemini]`): wraps `google-genai` generate content, env `ADMINA_GEMINI_API_KEY`/`ADMINA_GEMINI_MODEL`.
- vLLM model adapter: thin `OpenAIAdapter` subclass pointing at `http://localhost:8000/v1` by default (`ADMINA_VLLM_BASE_URL`/`ADMINA_VLLM_MODEL`); `supports_model` always returns `True`.

## Plan 08 — retry

### Added
- RetryPolicy + run_with_retry executor (admina.sdk) and RetryableUpstreamError/TerminalUpstreamError markers — vendored, no new dependency.

### Fixed
- The OpenAI and Ollama adapters now offload their blocking SDK calls via asyncio.to_thread (consistent with the new adapters), so the event loop is not blocked and per-attempt retry timeouts can fire.

### Added (continued)
- GovernedModel(retry=RetryPolicy(...)) retries the upstream model call on transient errors (default None = single attempt, unchanged).

## Carry-forward / tracked for later plans (not yet shipped)

These surfaced during reviews and are deliberately deferred:

- **Plan 03b (SDK half of D2):** port the server-side fixes into the SDK —
  `governed_agent._collect_strings` still scans dict values only (not keys);
  `governed_agent._redact_dict` redacts values only with no collision-safe key
  handling (reuse `domains.governance._deep_redact` / `redact_response_result`);
  per-call `uuid4()` session_id breaks loop-breaker continuity (finding G);
  GovernedModel default full protection + per-stage opt-out flags (finding I);
  GovernedData classifies ingested content, not the source locator (finding J).
- **Release (Plan 07) decisions:** the `/api/v1/validate` `MODIFY`→`REDACT` rename
  is a coordinated breaking change (n8n node + CheshireCat + OpenClaw + tests) —
  deferred, flag to maintainer. The blocked-validate `checks` object no longer
  carries a `pii_redaction` entry (read with `.get()`) — must land in the real
  CHANGELOG as a minor consumer note.
- **Minor:** the proxy forensic record serializes `pipeline_result.checks`
  directly, so it omits `would_action` (the dashboard reads it from ClickHouse,
  which does carry it — no functional gap). Align only if forensic-based
  would-have-blocked analytics is ever wanted.
- **Forensic (deferred):** the `verify_chain` count/head anchor catches naive tail
  truncation, but an attacker who also rewrites the mutable `_chain_state.json` to
  match a truncation defeats it — defending that needs a signed/anchored state file.
  S3 WORM Object Lock already protects record objects on that backend. Tracked, not 0.10.
- **Future option:** two `# follow-up: optional fail-closed mode` markers
  (guards are fail-open by design; a configurable fail-closed mode is a tracked
  future option, not 0.10).
