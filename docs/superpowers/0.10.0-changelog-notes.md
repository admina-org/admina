# 0.10.0 — running CHANGELOG notes

Accumulated as each plan lands, assembled into the real `CHANGELOG.md`
`## [0.10.0]` section by Plan 07 (release mechanics). Tone: neutral-technical,
Keep-a-Changelog headings (Added/Changed/Removed/Fixed/Documentation/Internal).

---

## Phase 0 (Plan 01) — plugin loop, config, dedup

### Fixed
- Builtin plugins register under their declared `name` (e.g. `ollama`, `apikey`)
  instead of a lower-cased class name.
- `admina plugin new` scaffolds working plugins: async methods matching every ABC,
  `admina-framework` dependency with the correct version floor, Python 3.11 requirement,
  and an `admina.plugins` entry-point so installed plugins are discoverable.
- `admina.yaml` `schema_version` is now parsed (was silently ignored — the loader read a
  nonexistent `version` key).
- OISG criterion S2 ("cryptographic agent identity") reads the configured API key
  instead of a nonexistent attribute.

### Added
- `admina.yaml` `plugins:` list and a new `plugin_config:` block are wired into plugin
  discovery and instantiation; plugins whose `__init__` accepts a `config` parameter
  receive their block.

### Changed
- The duplicated SDK adapter/connector ABCs are removed; `admina.sdk` re-exports the
  canonical `admina.plugins.base` definitions (single type for one contract).
- The dashboard SPA is single-sourced from the packaged copy; the diverged Docker root
  copy is removed.

## Plan 02 (D1) — unified engine acquisition

### Added
- `ADMINA_ENGINE=auto|python|rust` selects the governance engine backend uniformly
  across proxy, SDK, and integrations (unrecognized value raises).
- Typed `agent_security.firewall.custom_patterns` / `disabled_categories` config fields.

### Changed
- Governance engines (firewall, PII, loop breaker) are acquired through a single
  `admina.engines` package. SDK governed primitives and LangChain/CrewAI callbacks now
  gain Rust acceleration (firewall + loop breaker) under `auto` when `admina-core` is
  installed — previously proxy-only.
- SDK and integration callbacks now honor `admina.yaml` firewall overrides — previously
  proxy-only (and, via the broken `cfg.raw` path, effectively nothing).
- The `pii_engine` config key is now live (`spacy-regex` shipped; `presidio` reserved for
  0.10 behind `admina-framework[presidio]`).
- PII redaction stays on the Python engine by default even when Rust is installed
  (recall-safe: the Rust scanner does not cover EU national IDs or NER person/org names);
  Rust PII is opt-in via `ADMINA_ENGINE=rust`. Firewall and loop breaker remain
  Rust-accelerated under `auto`.

### Fixed
- `admina.yaml` firewall `custom_patterns` / `disabled_categories` now actually reach the
  firewall (the previous `cfg.raw` access path never existed, so overrides were dead).
- Rust engine `get_stats()` is normalized to the Python schema (Prometheus metrics were
  silently keyed differently for the Rust backend).
- When firewall overrides are present, `get_firewall()` uses the Python bridge so
  operator patterns are never silently ignored (the Rust firewall API cannot receive
  custom patterns).

### Internal
- `admina/proxy/engine_bridge.py` is now a re-export shim over `admina.engines`.

## Plan 03 — D2 server surfaces

### Fixed
- Firewall/PII scanning now covers dict keys, not just values (injection or PII in a field name is no longer skipped).
